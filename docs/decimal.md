# 小数坐标与统一十进制网格

## 开放折线与闭合区域求交（Unreleased）

`intersect_polylines_d(paths, clip, precision=, fill_rule=, limits=)` 与 `difference_polylines_d(paths, clip, precision=, fill_rule=, limits=)` 默认 Precision=3，支持 0—6；EvenOdd 默认，NonZero 可选。求交与求差各有整数／小数入口，四个接口均为 Unreleased，不在注册表 0.3.2 中。源码网页已提供两种模式的求交，求差尚未接入。完整边界及片段契约见[开放折线区域裁剪](lineclip.md)。

小数求差只为现有 `decimal_line_clip_execute` 增加私有模式透传，显式使用 KeepOutside；旧小数求交继续默认 KeepInside，不增加逻辑容器或原费用。不调用公开整数求差另建账，也不改整数事件、分类、舍入或连接。求差保留最终区域外部与孔洞中的非零区间，剔除内部及正长度边界重合区间；输出切分端点仍可在边界上，不能称所有输出点严格位于区域外。

先以整批原始数量和坐标预检，再用一次 `decimal_quantize(..., closed=false)` 共同量化路线与区域，保持跨两侧碰撞表。不同原始位置量化合并报错，完全相同坐标重复允许；不同于树查询允许量化重合的约定。之后仅对 clip 逐条使用既有 `decimal_closed`，位置索引为原始 paths.length()+clip 索引。开放路线允许空、单点、两点及重复点，不套用闭合退化检查；非空 clip 必须存在三个不同非共线网格点，空轮廓允许。不用有向面积为零排除自交区域。

数值顺序为原始 Double → 同一十进制网格 Int64 → 整数区域规范化 → BigInt 精确有理事件 → 网格交点半整数远离零舍入 → 原 Precision 解码。Precision 会影响区域、交点及片段；不额外浮点求交、不加 epsilon，也不恢复理想实数几何。零坐标沿用正零解码，舍入后塌缩、连续去重及跨剔除区间分段均由整数入口决定。

独立 `decimal_line_clip_execute` 不修改旧 `decimal_execute`，也不调用公开整数函数另建账。原始两侧路径、重复顶点共同占输入额度；小数预检、量化容器／碰撞表、clip 有效性检查、整数入口自身完整预检、区域和事件求值、DecimalOutput 解码都在同一账本累计。保留整数预检真实费用，不增加跳过开关。每个 clip 外层访问另计 1 工作，闭合检查和其他阶段复用原收费。传入限制与历史消费保持权威，不重置、不退款；整数成功后解码仍可失败，空区域也不能绕过量化检查。

错误沿用 DecimalParameters、DecimalQuantize、整数实际阶段及 DecimalOutput；路线在前、区域在后的组合原始位置不变，无原始来源的生成或输出位置为 None。失败不修改输入、不返回部分结果，内外数组复制隔离，重试独立。既有参考清单和数量没有变化，不宣称覆盖新小数入口。

## 已发布小数能力

下述增量能力自 **0.3.0** 提供，见[发布记录](release-0.3.0.md)。0.3.1 只修正文档表述，不改变运行库行为或接口；带 Commit 编号的验收记录按原阶段解释。

## 小数 Minkowski 孔洞树（自 0.3.0）

`minkowski_sum_tree_d(pattern, path, path_is_closed, precision=, limits=)` 默认 Precision=3（0—6），复用两输入共同预检、开放规则量化和碰撞表。原始索引固定为图案 0、路线 1，不先分别量化，不调用 `decimal_closed`，不根据有向面积丢弃图案。图案与路线按同一网格求和，生成坐标继续检查整数核心范围；参数锚点、路线开闭及不额外填满端点／内部的语义不变。

独立适配进入私有泛型扫掠，最终 Union 回调内构建保留共线点的整数树，再 `decimal_tree_output`。层级直接复制，不重新判断浮点包含关系，也不调用公开整数树入口另建预算。量化、矩阵、四边形、扫描、PolyTree 构建和 DecimalOutput 存储／解码共享账本，历史消费和传入限制保持权威。转换可能在整数树成功后失败，扫描仍清理且不返回部分树；旧小数平铺调度和费用路径不变。

树与平铺均保留共线输出，访问器仍复制隔离；空结果沿原生成及扫描流程，不能绕过数量、坐标或量化检查。输入量化和网格输出不保证保留无限小数细节。新树入口已随 0.3.0 发布，网页已接入整数／小数扫掠树，旧参考不作为新树能力的已执行证明。

## 小数闭合窗口孔洞树（自 0.3.0）

`rect_clip_polygons_tree_d(rect : BoundsD, paths, precision=, fill_rule=, limits=)` 默认 Precision=3（0—6）、EvenOdd，也支持 NonZero。复用窗口参数检查、独立窗口量化及闭合路径共同量化，再进入整数窗口公共执行函数；最终求交回调内先构建整数树，再转换小数树。窗口不进入路径碰撞表、不占原始输入额度，原始空窗口与量化塌缩继续区别处理，旧小数平铺调度和量化规则不变。

参数检查、量化、窗口存储、扫描、整数树和小数转换共享同一账本，已有限制与历史消费保持权威。PolyTree 与 DecimalOutput 分别收取树构建和小数存储／解码费用，后者可能在整数树成功后耗尽；无原始对应关系的位置为 None。转换失败仍经过扫描清理，不发布部分树，重试独立。空分支使用已计费 `tree_empty` 后转换，不追加扫描或平铺存储；平铺入口不承担树费用。

小数树直接复制裁剪后整数层级，不重算浮点包含。窗口切开孔洞后可能得到无孩子的凹口外轮廓，输出不沿用输入层级；访问器复制隔离及 `to_paths()` 丢失显式层级的约定不变。已随 0.3.0 发布，网页已接入整数／小数闭合窗口树。

## 小数批量描边孔洞树（自 0.3.0）

`stroke_polylines_tree_d(paths, width, precision=, cap=, options=, limits=)` 默认 Precision=3（0—6），将整批独立开放路线共同量化；width 为原单位完整宽度，与 ArcTolerance 一同缩放，MiterLimit 无量纲。原始预检、开放量化和缩放后，直接复用批量公共执行流程，一次清理后在最终提取回调中 `tree_build` 并 `decimal_tree_output`。转换失败经过扫描清理，不重新执行公开整数入口，不重建浮点包含关系。

小数树直接保留量化后整数覆盖区域的层级，不保留来源路线归属。传入账本的限制和历史消费保持权威，原始数量整批累计，量化、整理、生成、清理、整数树与小数树同账，不退款或提高默认值。整数树阶段为 PolyTree，小数存储和解码为 DecimalOutput；无原始输入关系的位置为 None。整数树成功后，转换仍可能因预算不足失败。

空分支先保留已发生的数组费用，再收费构造整数空树及小数空树；零宽度仍检查全部输入和量化碰撞。旧小数平铺入口和调度保持不变，平铺调用不承担树构建或小数树费用。访问器复制隔离沿用既有约定，`to_paths()` 丢失显式层级。

## 小数开放折线矩形裁剪（自 0.3.0）

`rect_clip_lines_d(rect : BoundsD, paths, precision=, limits=)` 默认 Precision=3（0—6），窗口复用独立参数校验和量化，全部路线在同一次 `closed=false` 量化中处理。路线不要求三个非共线点，不隐式闭合，也不跨路线拼接。不同原始位置落在同一网格点会报错，相同位置允许重复。窗口不进入路线碰撞表、不占原始路径／顶点额度；原始点数整批累计，含重复点。

数值分三段：输入按既有半整数远离零量化；网格裁剪使用整数开放裁剪的求交与向零截断；输出将整数坐标除以共同倍率，零解码为正零。不替换为闭合 Boolean 交点规则，不额外吸附、钳制或简化；结果来自量化网格，不保证理想实数裁剪的无限精度。

原始零宽或零高窗口仍检查全部输入及量化碰撞，原本有面积而量化后塌缩的窗口报 QuantizationFailure。窗口检查、独立 Bounds64、路线存储、整数裁剪和解码共用账本，注入限制与历史消费保持权威；空结果计费，不退款或重置。整数裁剪成功后，解码仍可能在 DecimalOutput 失败。窗口错误位置为 None，路线错误保留原始索引，输出不伪造来源位置。失败不修改输入、不返回部分片段，输出内外数组与输入隔离。

库新增此小数入口，当前网页窗口裁剪支持整数与小数开放路线。

## 小数闭合区域矩形裁剪（自 0.3.0）

`rect_clip_polygons_d(rect : BoundsD, paths, precision=, fill_rule=, limits=)` 默认 Precision=3（0—6）、EvenOdd，也支持 NonZero。窗口参数与闭合区域使用相同网格和半整数远离零舍入，整数求交沿用 Boolean 网格规则，输出由 `decimal_output` 解码，零坐标为正零；Double 不保证无限十进制精度。它不采用开放折线的向零截断求交路线。

BoundsD 仅保存四个不可变原始 Double；入口检查有限性、Precision 对应范围及原始顺序，窗口错误位置为 None，顺序错误阶段为 RectClipParameters。窗口角点单独量化，不加入路径碰撞表，也不占原始路径／顶点额度；区域各路径仍共同检查量化碰撞，非空轮廓必须满足既有闭合网格有效性。窗口边界与路径顶点接触不会被误报为输入位置合并。

原始零宽／零高窗口是合法空窗口，仍完成原始数量、坐标和闭合路径量化检查；原本有面积而量化后宽或高为零时，返回 DecimalQuantize 的 QuantizationFailure，不扩宽或当作普通空结果。没有自动简化或拓扑修复；树输出另用 `rect_clip_polygons_tree_d`。

同一账本覆盖窗口参数检查（5 单位工作）、独立窗口量化（1 个 Bounds64 节点、4 单位工作）、路径预检与量化、整数窗口构造、扫描、提取及解码。窗口临时参数数组不会建立。传入账本的限制和历史消费保持权威，不重置或退款；空结果也计费。整数求值完成后，解码仍可能因余额不足返回 DecimalOutput 资源错误。原始路径错误保留索引，扫描保留实际引擎阶段；失败不返回部分结果、不修改输入。

## 小数多路线批量描边（自 0.3.0）

`stroke_polylines_d(paths, width, precision=, cap=, options=, limits=)` 返回合并后的平铺闭合区域。Precision 默认 3，支持 0—6；所有独立开放路线在同一次量化中使用共同碰撞检查，不要求三点非共线，也不按面积删除路线。不同原始位置落到同一网格点会报错，相同位置允许重复，随后按开放规则整理；显式返回起点仍采用开放端点语义。量化可能改变可表达形状，不保证保留全部原始小数细节。

width 是原单位完整宽度，和 ArcTolerance 一同按十进制倍率缩放，MiterLimit 无量纲，端点和连接原样传递。先检查有限非负宽度、样式及整批原始数量和坐标，再共同量化。只有缩放后的完整宽度小于 1 才采用整数空结果分支；零宽度也不能绕过后续路线的量化碰撞检查。

一个账本覆盖原始预检、量化、路线整理、生成、一次统一清理、整数提取和小数解码；空路线与重复顶点仍计入原始额度。传入账本的限制和历史用量保持权威，不退款。整数求值成功后仍可能在 DecimalOutput 因额度不足而失败，整批不返回部分结果；生成越界映射回原单位并保留实际阶段。输入（含共享路线数组）与输出存储隔离。

## 小数 Minkowski Sum（自 0.3.0）

`minkowski_sum_d` 将图案（路径索引 0）和路线（索引 1）在同一次量化中处理，Precision 默认 3、范围 0—6。两输入分别按半整数远离零舍入，再执行整数坐标相加；不先用 Double 相加。共同碰撞检查拒绝不同原始位置落在同一网格点，包括跨图案与路线的碰撞；相同位置允许重复且不自行去重。不启用闭合面域的三点非共线检查。

原始路径额度为两条，包含空路径；顶点合计且包含重复点。一个账本覆盖预检、量化、平移矩阵、四边形、清理、整数提取及 `decimal_output` 解码，传入账本的限制和历史用量保持权威。整数阶段成功后仍可能在 DecimalOutput 因余额不足而失败，不返回部分结果。零坐标解码为正零。生成越界经 `decimal_error` 映射到原单位，保留 MinkowskiGenerate 和既有位置语义。

以下单路线描边树、偏移树及 Boolean 小数树自 **0.2.0** 提供，见[正式发布记录](release-0.2.0.md)。旧锚点继续兼容已有链接，历史验收记录保留原提交归属。

## 小数描边树（自 0.2.0）

`stroke_tree_d(path, width, precision=, cap=, options=, limits=)` 返回 `Result[PolyTreeD, ClipError]`，默认 Precision=3、Butt，支持三种端点和四种连接，没有填充规则参数。此接口尚未包含在 0.1.0。width 是原单位完整宽度，width 和 ArcTolerance 按十进制倍率缩放，MiterLimit 保持无量纲。

独立适配使用开放量化规则，不要求三点非共线；先检查原单位参数，再量化并调用共享描边执行器。零宽度也不能绕过量化合并、坐标和原始数量检查。小宽度判断针对缩放后的完整 width：Precision=3 时原单位 .001 对应网格宽度 1，并不提前返回空树。实际边界仍受生成坐标舍入影响。

新建账本使用 StrokeGenerate / StrokeCleanup，传入账本的限制及历史用量保持权威。预检、量化、开放整理、生成、清理、整数树和下文的小数转换共用预算，释放不退款。正常转换放在清理扫描的提取回调内，失败也执行清理；快捷空结果不启动扫描，先计费构造整数空树，再计费解码空树。树构建标记 PolyTree、解码标记 DecimalOutput，其他错误保留实际阶段，输出位置不冒充输入索引。坐标转换只复制整数拓扑，首尾重合仍按开放路线处理。

## 小数孔洞树（自 0.2.0）

`offset_tree_d(paths, delta, precision=, fill_rule=, options=, limits=)` 返回 `Result[PolyTreeD, ClipError]`，自 0.2.0 提供。默认 Precision=3、NonZero，沿用平铺偏移的参数验证和缩放规则；delta 与 ArcTolerance 随十进制倍率缩放，MiterLimit 不缩放。小距离判断针对缩放后的 delta，例如 Precision=3 时原单位 .001 对应整数距离 1，不能按原单位与 .5 比较。

偏移树在共同规范化、生成与最终 Positive Union 后构建整数树，再通过下述同一转换函数解码。小距离在规范化扫描回调内构建并解码，规范化为空时用已计费的空树辅助，不追加扫描。正常及小距离回调失败均沿用所属扫描的清理路径，错误保留原有阶段。整个流程共用累计预算，不退款。小数树保存最终量化区域的层级，Precision、偏移造成的合并或孔洞消失都可能改变结果，不能沿用输入层级。该入口尚未包含在 0.1.0。

`boolean_tree_d(subject, clip, operation, precision=, fill_rule=, limits=)` 返回 `Result[PolyTreeD, ClipError]`。参数与默认值同 `boolean_op_d`：Precision 默认 3、范围 0—6，EvenOdd 默认，NonZero 可选，四种 Boolean 操作均可用。**此入口自 0.2.0 提供，0.1.0 不包含它**。下文原有参考数量与 Commit 13 记录仍是历史证据。

一次调用依次执行原始预检、闭合规则量化、私有 Boolean 求值、整数树构建及验证、小数树转换、扫描清理。转换在提取回调内完成，失败也经过同一清理路径，并沿用既有小数错误映射。旧 `decimal_execute`、整数树与平铺小数入口不变。

转换直接迭代整数节点数组，复制父、孩子、根索引和深度，仅用既有 `decimal_value` 解码坐标；没有递归，也不重新判断浮点包含、面积或方向。层级来自量化后的整数区域，Precision 变化可能影响可表达关系；输出仍是 Double，零解码为正零。

| 访问器 | 契约 |
| --- | --- |
| `PolyTreeD::roots()` | 新根视图数组，根深度 1，无虚构轮廓 |
| `PolyTreeD::to_paths()` | 复制外层及每条路径，丢失显式父子关系，顺序未指定 |
| `PolyNodeD::contour()` | 独立点数组，不反转、不整理 |
| `PolyNodeD::children()` | 新孩子视图数组，视图共享只读内部数据 |
| `PolyNodeD::depth()` / `is_hole()` | 外轮廓 1、孔洞 2、岛 3，偶数层为孔洞 |

没有公共构造器、可变节点或父节点访问器。不可变 PointD 可以在访问器副本间复用；修改输入、访问器数组或另一次调用结果不会影响树。空区域返回成功空树。

所有阶段共用累计账本，整数树仍标记 `PolyTree`，新增存储、解码与最终构建使用 `DecimalOutput`，位置索引均为 None。整数中间结果释放不退款。

| 新增转换分配或工作 | 节点额度 | 工作额度 |
| --- | ---: | ---: |
| 节点与根容器 | 2 | 0 |
| 每节点：记录、外层槽、轮廓与孩子容器 | 4 | 1（访问节点） |
| 每输出点：PointD 与数组槽 | 2 | 1（两轴解码） |
| 每根或孩子索引槽 | 1 | 1（复制索引） |
| 数据与树对象 | 2 | 1（最终构建） |

分配前收费。N 节点、V 点时，根槽与孩子槽合计 N，新增节点费为 `4 + 5*N + 2*V`，工作费为 `1 + 2*N + V`；空树仍需 4 节点、1 工作。这是逻辑单位，不是物理字节或数组容量。执行结束后访问器的按需复制成本沿用整数树约定。额度不足返回完整 Err，不发布部分树，也不将输出节点号当作输入位置。

受检 CLI 的 `run_decimal_tree_example` 构造边界为 ±5.25、±3.25、±1.25 的三层矩形，`run_offset_tree_example` 检查整数／小数偏移树，`run_stroke_tree_example` 检查普通路线和带孔描边的完整轮廓及层级。运行 `moon run --target native cmd/example`。33 项 `decimal tree: *`、27 项 `offset tree: *` 和 29 项 `stroke tree: *` 测试覆盖完整预期、层级、开放端点、隔离、预算边界和失败清理；源码全量为 2234+33+27+29=2323。既有 1384 个参考案例、2276 项能力检查不变，不能解释为已覆盖新树入口。

## 既有小数数据模型

PointD 保存原始 Double，字段不可变；PathD/PathsD 是有序可变数组。构造不量化、不去重，Eq 逐字段比较且没有 epsilon。copy_path_d 复制点数组，copy_paths_d 复制外层及每条内层数组，别名输入也得到独立副本。Double 存储不等于任意十进制精确计算。

## 精度与调用

Precision::new(digits) 返回 Result，支持 0—6，默认 3；digits() 读取位数，字段私有。Precision 只保存不可变位数，无账本、缓存或其他执行状态。倍率由固定表 1、10、100、1000、10000、100000、1000000 选择，不使用运行时浮点幂。

| 入口 | 默认及参数单位 |
| --- | --- |
| boolean_op_d(subject, clip, operation, precision=, fill_rule=, limits=) | EvenOdd；整数核心四种 Boolean 操作 |
| offset_polygons_d(paths, delta, precision=, fill_rule=, options=, limits=) | NonZero；delta 为原单位，四种 Join |
| stroke_polyline_d(path, width, precision=, cap=, options=, limits=) | Butt；width 为完整原单位宽度 |

[可运行示例](../cmd/example/main.mbt)的 run_decimal_example 共用一个 Precision(3)，实际执行负坐标 Union → Offset，以及 Stroke → Intersection；每步检查 Result 并断言完整矩形轮廓。Union 为 [-1.25,-.25]—[2.25,1.25]，偏移 .2 后为 [-1.45,-.45]—[2.45,1.45]；路线 (-1,0)→(3,0)、宽 .4 与遮罩求交后为 [0,-.2]—[2,.2]。失败立即停止，没有空结果回退。运行 `moon run --target native cmd/example`，示例与检查入口一同构建执行。

## 坐标量化与范围

输入先检查有限性和原单位范围，再乘 scale，复查有限性及网格范围，最后比较整数部分与尾数 .5，执行半整数远离零；不是 floor(x+.5)。例如 .49999999999999994→0、.5→1、.5000000000000001→1，负数对应 0、-1、-1。先加 .5 会让相邻值在加法舍入时跨过边界，故不采用。输入量化、既有扫描 ties-to-even 投影、固定参考偏移生成的舍入是三个不同环节，整数行为未改变。

| precision | scale | 原单位每轴范围（含边界） |
| ---: | ---: | ---: |
| 0 | 1 | ±1,000,000,000 |
| 1 | 10 | ±100,000,000 |
| 2 | 100 | ±10,000,000 |
| 3 | 1,000 | ±1,000,000 |
| 4 | 10,000 | ±100,000 |
| 5 | 100,000 | ±10,000 |
| 6 | 1,000,000 | ±1,000 |

原单位略超界也拒绝，不靠舍入拉回边界。极大有限坐标在乘法前就被范围检查拒绝；有限距离/容差的乘法溢出则为 NumericFailure。所有 Int64 转换均在检查之后。

输出只执行 coordinate64.to_double()/scale，零显式返回 +0.0；无字符串格式化、十进制截断或二次取整。网格整数本身在 Double 连续精确范围内，但除法结果仍为二进制浮点数。比较器同时验证完整整数轮廓，以及每个实际小数坐标精确等于对应整数除以倍率；不能只重新量化任意输出。

## 严格量化诊断

原本不同的位置落到同一网格点时返回 QuantizationFailure。检查跨同一路径、不同轮廓、两个 Boolean 操作数，按 subject 路径/顶点、再 clip 的顺序记录首次位置。+0.0/-0.0 是同一位置；原本完全相同的重复点允许，无 epsilon。辅助索引由同一执行预算约束。

非空闭合输入必须至少包含三个不同且不全共线的网格点；使用精确叉积检查，不按面积为零过滤自交轮廓。空轮廓允许。小数入口的严格契约不改变整数入口接受退化输入的行为。开放 Stroke 允许空路径/单点，但新出现的点合并先报错，即使宽度为零或很小也不跳过参数和输入检查。

- QuantizationFailure(location, axis?, first_location?, message)：非有限坐标携带轴；点合并携带冲突位置和首次位置，轴为 None；整个轮廓退化时顶点、轴和首次位置均为 None。说明为英文。
- DecimalCoordinateOutOfRange(location, axis, value, digits)：value 是原单位 Double，digits 表明范围，非法值不塞进旧 Int64 字段。
- DecimalParameters、DecimalQuantize、DecimalOutput 分别定位本层参数、量化和输出费用。内部生成坐标越界映射回原单位但保留 OffsetGenerate/StrokeGenerate 等原阶段；其他 NumericFailure、ResourceLimitExceeded、ExecutionFailure 保留真实类型与具体阶段。

量化数组保留每条原始路径与每个顶点的位置，不先整理、不标记为内部生成输入。下一公开调用收到小数中间结果时会重新验证并量化；不同精度下可能出现新的量化失败。

## 长度参数传播

| 参数 | 送入私有整数核心的值 |
| --- | --- |
| 坐标 | coordinate ×scale 后量化 |
| delta | delta ×scale，仍为 Double |
| 完整 width | width ×scale，核心再除以 2 |
| 正 ArcTolerance | tolerance ×scale |
| ArcTolerance=0 | 保留自动精度哨兵 |
| MiterLimit | 无量纲，保持原值 |

独立构造缩放 OffsetOptions，原选项不变。precision=3 时，delta=.2→200，width=.4→400、每侧200，ArcTolerance=.025→25，MiterLimit=4仍为4。小距离阈值为原单位 .5/scale，小宽度阈值为 1/scale；极小正容差的底层 1e-12 分支判断在网格单位进行。距离不能先转整数。

## 累计资源与所有权

每次公开小数调用建立一个账本：原始预检 → 量化副本与全局合并索引 → 私有整数求值/清理/提取 → 小数结果。直接复用 boolean_compute、offset_execute、stroke_execute，不调用会重建账本的公开整数函数。已传入账本的限制和历史计数始终权威。默认内部上限仍为500000节点、5000000工作量；原始路径/顶点限制仍为10000/100000，输入额度不是所有输入都能在执行额度内完成的保证。

| 小数阶段 | 计费内容 |
| --- | --- |
| 预检 | 每条原路径和每个原始顶点的工作；重复点也计入原始数量 |
| 量化 | 两个结果容器与合并索引；每路径容器/外层槽；逐点查找键、索引条目/来源记录、新网格点及数组槽 |
| 有效性 | 逐点寻找不同点与精确共线检查 |
| 整数核心 | 保持[原累计计费](composition.md)，包含再次扫描真实量化输入 |
| 小数输出 | 结果外层、每条内层和外层槽、每个 PointD 与点槽、逐点解码工作 |

所有存储先扣费，两项额度检查成功后才同时更新，不退款。整数求值成功并不保证剩余费用足以输出小数结果；任何失败都返回 Err，不泄露部分结果。临时释放不依赖剩余预算，结果内外数组与输入隔离。同一 Precision 在独立公开调用间不共享预算。

## 两类独立参考与误差边界

固定 [ClipperD 源码](https://raw.githubusercontent.com/AngusJohnson/Clipper2/21ebba05db8894f0c7217ad35ea518080f324946/CPP/Clipper2Lib/include/clipper2/clipper.engine.h) 使用2的幂作为倍率；[InflatePaths(PathsD)](https://raw.githubusercontent.com/AngusJohnson/Clipper2/21ebba05db8894f0c7217ad35ea518080f324946/CPP/Clipper2Lib/include/clipper2/clipper.h)使用十进制倍率。MoonClip统一十进制，不宣称与所有 ClipperD 输入逐点一致。

196 条 DecimalGrid 由适配器独立 std::round 量化后执行固定整数路线：Boolean112（两构型×四操作×两填充×七精度）、Offset48（四连接×正负×两填充×0/3/6）、Stroke36（四连接×三端点×0/3/6）。偏移仍共同规范化，描边仍开放路径并解释完整宽度，包括合法的次网格空结果。

24 条 ClipperDCommonGrid 真正执行 ClipperD，输入与结果位于两者共同网格；先验证原始浮点输出在目标网格上，再保存整数见证。偏离网格就失败，不能强行重新量化。共同网格不限于整数，但只有这24个固定输入构成当前兼容证据。路线、操作、精度及哈希全部写入独立v5协议，网格与原单位结果均保存。旧772条不变，总数992；同一案例的两种表示不算两条输入。

单次量化在无乘法舍入跨界的理想网格上，坐标舍入偏差最多半格；原始 Double 表示和乘法还有浮点舍入。该局部界不是整体几何误差或拓扑保证。输入量化、交点网格投影、圆弧近似、输出 Double 解码是不同误差来源。严格合并/退化检查只拒绝已定义的问题，不能替代任意拓扑修复。

80 项功能分为类型/复制/精度12、量化20、单位与范围20、预算/错误16、组合隔离12；native和JS执行同一批。新增220对照后各目标1714项。离线工具209=179+30、真实适配器65=51+14另计；本地、普通Linux CI和独立参考CI分别验证，见[兼容报告](compatibility.md)。原规划不变，简化与删点报告留给Commit14。


## 小数树点定位（自 0.3.0，Commit 50）

`PolyTreeD::locate` 和 `locate_many` 使用树原建树 Precision 量化查询点，返回 TreePointLocationD 及原小数节点视图；不另传精度。接近边界的点可能量化到边界，不同查询点量化到同一点允许发生，不触发几何输入碰撞错误。空树同样检查有限性和原精度范围。

现有全部小数树在 decimal_tree_output 中保存私有精度，不增加元数据容器或改变原转换费用、源树复制隔离；查询只临时恢复一次整数视图，复用精确定位并按原索引映射回来，批量共享恢复与求值预算。恢复范围推导、严格回解码和计费见[树点定位](polytree-query.md)。结果是网格位置，无浮点 epsilon 或实数无限精度承诺。Commit 50 当时的网页仍只支持整数查询；当前六类小数区域树均已接入，见[演示说明](demo.md)。
