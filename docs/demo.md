# MoonClip 交互演示

本页新增能力已随 **0.3.0 正式发布**，见[发布记录](release-0.3.0.md)。下文 Unreleased 与 Commit 标记保留各笔开发阶段归属；注册表包内文字是冻结候选快照，本页为发布后的状态更新。

## 当前操作入口（0.3.0 对应源码）

使用[固定工具链](toolchain.md)和 Node.js 20 以上，在仓库 `demo` 目录运行 `npm run dev`，服务启动后访问 **http://127.0.0.1:4173/**。没有 npm 依赖，不需要 npm install。演示调用真实 MoonBit 核心，前端不自行缩放、量化或求交；下表库能力已随 Mooncakes 0.3.0 提供，演示仍从仓库启动。

| 操作 | 坐标模式 | 结果结构 | 点定位 |
| --- | --- | --- | --- |
| Boolean、Offset、单路线加宽 | 整数／小数 | 平铺／树 | 树可单点／批量查询 |
| 批量加宽、图案扫掠 | 整数／小数 | 平铺／树 | 树可单点／批量查询 |
| 窗口裁剪：闭合区域 | 整数／小数 | 平铺／树 | 树可单点／批量查询 |
| 窗口裁剪：开放路线 | 整数／小数 | 有序开放片段 | 不支持 |

选择场景、坐标模式及案例，编辑点数组和参数后点击计算。需要层级时选择孔洞树，可展开节点并独立选择边界高亮；空树也是有效结果。修改输入、精度或参数立即失效旧结果并禁用导出，失败不保留部分树或查询，迟到响应受请求编号保护。

六类区域树都可启用单点或批量定位，每批最多 32 点，允许空列表并保留重复项。选择结果行只更新查询点强调和命中高亮，不重新计算；手动树选择与查询高亮独立。小数查询使用本次建树 Precision，先量化再判断，靠近边界的点可能量化到边界；图中标记和列表保留原始输入坐标，不代表量化后的判定位置。

区域 SVG 使用闭合轮廓和 NonZero 填充，开放片段 SVG 不闭合且无填充；均只导出结果。JSON 保存真实请求和结果：平铺区域 v1、树及可选查询 v2、开放片段 v3。重放时重新提交 request，不读取导出结果冒充计算。详细契约见[增量升级说明](upgrade-incremental.md)，各阶段的下载重放、截图和窄屏观察见[验收索引](acceptance-incremental.md#演示与浏览器证据)。

本笔普通 CI 为 docs 文档范围，不构建演示或执行桥接检查。功能验收按各自 scope 运行；查询、窗口、批量描边、扫掠各自复用三项定向检查，不累加为新增独立测试总数。临时窄屏容器异常仍为归因未确认，记录见[Commit 51 验收](demo-acceptance.md#commit-51小数树单点与批量定位增量验收)。

## Commit 51：小数树单点与批量定位（Unreleased）

六类区域树现均支持整数／小数查询：Boolean、Offset、单路线 Stroke、批量 Stroke、闭合窗口裁剪及 Minkowski Sum。开放窗口裁剪及平铺仍拒绝 query，未知坐标模式明确拒绝。单点 point 与批量 points 二选一、批量最多 32 点且允许空列表的演示约定不变；整数仍检查安全整数，小数接受有限数值，不缩放或舍入输入。无查询请求和旧整数响应保持原格式。

小数请求解析为私有 DecimalTreeQuery，直接把 PointD 交给 `PolyTreeD::locate`／`locate_many`；批量只调用一次。公共四场景和批量、窗口两个提前返回路由均在本次生成的同一棵树上定位，再使用 encode_tree_d 编码同一树，轮廓和展示索引同源。命中依完整轮廓坐标与顺序、深度及孔洞标记唯一精确匹配，缺失、重复或歧义均失败，不读取核心私有索引，不做近似坐标匹配。错误保留核心阶段和查询点索引，失败不发布部分查询。

小数查询使用本次建树 Precision：先量化到树的网格，再判断区域位置；靠近边界的点可能被判为边界。例如 x=0 边界旁的 (-0.004,1)，Precision=2 为边界、3 为外部。控件和结果区明确提示：列表与图中标记保留原始输入坐标，标记不表示量化后的判定位置。单点在小数模式采用 step=any，整数恢复 step=1；批量按模式检查有限数值或安全整数，不截断、不去重。

修改模式、Precision、点或几何立即清除旧结果、列表、选择及有效导出；整数模式切回保留小数原值并明确报错。行选择只更新展示，查询和手动树选择仍独立，失败及迟到响应沿用原清理机制。SVG 仍只导出区域及孔洞，无查询标记或选择；v2 JSON 保存原请求、模式、建树 Precision、层级及完整查询，必须通过原请求重放，不读取已有结果冒充求值。v1、v3 不变，未增加协议版本。

本笔只扩展原有 `demo tree locate:` 三项，验证小数 Boolean 单点／批量及批量描边路由、精度差异和后续越界、v2 原始点重放；其余 Offset、单路线描边、窗口、Minkowski 小数树接线通过代码审查确认，没有铺组合矩阵。普通 CI 复用已有 demo-tree-locate，未改脚本、根库、公开接口、依赖或版本，保持 Unreleased。实际导出与窄屏观察见[增量验收](demo-acceptance.md#commit-51小数树单点与批量定位增量验收)；以下章节保留各笔当时范围。

## Commit 49：整数树批量点定位（Unreleased）

整数区域树的查询面板增加“单点／批量”。单点继续提交 `query: {point: [x,y]}`，批量提交 `query: {points: [[x,y], ...]}`；两字段必须二选一，缺失、同时提供或结构错误均拒绝。前端和桥接均限制批量最多 32 点，超出报错、不截断；这是演示限制，核心 `locate_many` 没有新增该上限。允许空列表，显示“0 个查询结果”，区域和有效导出仍保留。

桥接仅解析一次查询。各整数树路由统一对实际生成的同一棵树调用一次 `locate` 或 `locate_many`，随后同次编码树及轮廓；批量验证结果长度，再复用完整轮廓、深度及孔洞标记的唯一匹配。批量响应 query 含 `mode: batch`、原顺序 points 和逐项 results，每项仍为 point、status、node_indices。旧单点响应原结构不变。小数、平铺、开放路线窗口以及非整数查询继续拒绝，失败不发布部分树或查询列表。

批量列表保留输入序号与重复点，显示坐标、状态及命中节点属性，并汇总各状态数量。点击结果行只切换强调点位及其全部命中边界，不重新执行几何；Outside 清除查询边界，手动树选择仍独立。所有有效响应点位都绘制并纳入自适应视图，重复点可重叠，列表仍各自保留。编辑模式、点数组或几何参数立即清除旧列表、选择、高亮和有效导出；切换不支持组合会关闭查询，迟到响应受既有编号保护。

v2 JSON 直接复用既有深复制导出，保存完整批量请求、顺序、重复项和真实结果；重放重新求值并核对命中完整快照，不将展示索引当作永久编号。单点 v2 及无查询请求继续兼容。SVG 仍只导出区域，不包含点位、编号或高亮，不增加格式版本。

本笔扩展原有 `demo tree locate:` 三项，不新增测试块或 scope。普通 CI 切回已有 `demo-tree-locate`，只静态检查、构建一次并执行三项。浏览器实际下载、重放及有限窄屏观察见[增量验收](demo-acceptance.md#commit-49整数树批量点定位增量验收)。根库、公开接口、版本和标签未改，保持 Unreleased；以下 Commit 节保留历史范围。

## Commit 47：扩展整数树点定位（Unreleased）

点定位现已支持 Boolean、Offset、单路线描边、批量描边、闭合区域窗口裁剪和 Minkowski Sum 的整数树。必须选择整数坐标及树输出；窗口还必须选择闭合区域。小数树、平铺结果、开放窗口路线、非整数查询点及非法查询结构明确拒绝，不静默忽略 query。没有 query 的旧请求保持原行为。以下各 Commit 节保留当时范围，以本节为当前查询范围。

桥接统一使用私有查询与编码辅助：先对当前操作实际生成的树调用 `locate`，再编码同一棵树。批量描边和窗口裁剪的提前返回分支也使用该流程，不从平铺轮廓重新构树。命中节点通过完整点序列、深度和孔洞标记唯一匹配展示节点；缺失、歧义或查询失败均返回完整错误，不发布可导出的部分结果。轮廓与层级仍来自同次编码，展示索引仅在本次响应内有效。

查询控件提示“仅整数树”，查询的是操作完成后的区域。公共、批量及窗口请求均可携带 query；切换到小数、平铺或开放路线会关闭查询、清除旧结论及高亮。编辑输入、参数或查询点使旧结果立即失效，失败和迟到响应继续沿用原有清理与请求编号保护。手动节点选择与查询高亮互不覆盖。

`locate` 仍使用独立调用预算；每次提交包含区域重算和定位，页面耗时不是纯查询耗时，没有持久树缓存。v2 JSON 保存完整原请求、查询点、状态和命中索引；重放核对命中轮廓、深度及孔洞标记，不要求跨次索引稳定。关闭查询时响应和导出不残留 query。SVG 仍只导出区域，平铺 v1 和开放 v3 不变。

本笔调整原有 `demo tree locate:` 三项，分别覆盖公共扫掠树、批量树和窗口树路由，保留多边界及错误检查，使用批量树进行 JSON 重放。未新增测试块、scope、案例或依赖；普通 CI 复用 `demo-tree-locate`。实际下载和有限窄屏观察见[增量验收](demo-acceptance.md#commit-47扩展整数树点定位增量验收)。根库、公开接口、版本和标签不变，保持 Unreleased。

## Commit 46：Minkowski Sum 孔洞树（Unreleased）

“路线实验 → 图案扫掠”现在支持整数／小数、平铺／树四种组合，分别直接调用 `minkowski_sum`、`minkowski_sum_d`、`minkowski_sum_tree`、`minkowski_sum_tree_d`。默认仍为 paths；整数／小数树复用同一次 `encode_tree`／`encode_tree_d`，paths 和展示索引同源，不从平铺结果重新构树，也不排序、反向、去重或简化。未知输出、开启简化和扫掠查询请求明确拒绝，点定位仍只支持整数 Boolean Tree。

树面板复用既有根数、轮廓数、最大深度、节点深度及孔洞标记，还显示完整顶点数，可展开、收起、选择边界及清除选择；空树使用既有摘要。输出结构不再在控件更新时被强制重置。修改模式、Precision、图案、路线或开闭参数立即失效旧树和导出，失败清除选择，迟到响应仍受请求编号保护。图案保持相对锚点直接相加，树描述最终区域，不对应生成四边形；闭合路线可能留孔，不代表填满内部，节点轮廓保留共线点，不一定只有四点。

新增同一闭合矩形构造的整数／小数两个输入案例：整数图案 [-2,-1]—[2,1] 沿 [0,0]—[30,20] 的闭合矩形边界扫掠，小数将图案和路线统一除以 4、Precision=2。案例只保存输入和参数，计算结果均来自 MoonBit。案例加载按完整图案点序列匹配已有预设，否则显示“案例／自定义图案”，不显示与编辑内容不符的预设名。

平铺继续导出 v1 JSON，树沿用 v2，完整保存原始图案、路线、开闭参数、模式、Precision、实际轮廓和层级；SVG 仍只导出闭合 NonZero 区域及孔洞，保留全部轮廓顶点，不包含输入、锚点或选择辅助，不增加格式版本。重放核对完整坐标、顶点数、深度和父子关系，不用包围盒或面积代替。

既有筛选名 `demo decimal minkowski:` 保留，本笔在原有三项中同时覆盖整数／小数树，并保留小数平铺断言；移除另一旧用例中“扫掠树必须拒绝”的过时断言，新的拒绝范围由本笔三项覆盖。未新增测试块或 scope，CI 使用已有 `demo-minkowski-decimal`。实际下载、重放和窄屏观察见[增量验收](demo-acceptance.md#commit-46minkowski-sum-孔洞树增量验收)。未改根库、公开接口、依赖或版本，保持 Unreleased。

## Commit 44：窗口裁剪孔洞树（Unreleased）

“窗口裁剪 → 闭合区域”现在可以选择“平铺轮廓／孔洞层级”。整数树直接调用 `rect_clip_polygons_tree`，小数树直接调用 `rect_clip_polygons_tree_d`，分别复用 `encode_tree`／`encode_tree_d`。轮廓和节点索引来自同一次编码，不排序、不从平铺结果重新构树；响应保留 `geometry: closed-regions`，树输出附带 `output: tree` 及完整 tree。缺省 input_kind 仍为 lines，缺省 output 仍为 paths；开放路线拒绝树输出，未知输出和窗口查询字段明确拒绝。

闭合树复用已有层级面板，可查看根数、轮廓数、深度及孔洞标记，展开、折叠、选择边界或清除选择。树表示裁剪后的区域：孔洞完全在窗口内可以保留，被窗口切开后可能变成外边界凹口。区域始终完整填充，选择只高亮边界；窗口仍单独虚线显示，空树显示明确摘要且可导出。修改精度或填充规则保留树选择，编辑内容使旧结果立即失效；切回开放路线强制 paths，隐藏树并清除选择。失败和迟到响应继续沿用现有清理与请求编号保护，点定位仅在整数 Boolean Tree 显示。

导出直接复用现有格式：开放片段为 v3 JSON／开放 SVG，闭合平铺为 v1 JSON，闭合树为 v2 JSON；两类闭合 SVG 都只导出完整区域及孔洞，不带窗口、输入或选择。树 JSON 保存原始窗口、轮廓、input_kind、mode、Precision、fill_rule 和 output，以及实际轮廓和父子关系；重放核对完整轮廓与层级，节点索引不是跨计算永久标识。

本笔使用已有案例，调整原有 `demo rectclip:` 三项检查，没有新增测试块、scope、案例、依赖或公开接口。同 SHA CI 使用已有 `demo-rectclip`；实际下载、重放、凹口、空树和窄屏观察见[增量验收](demo-acceptance.md#commit-44窗口裁剪孔洞树增量验收)。下面各 Commit 节保留对应历史范围，新演示保持 Unreleased。

## Commit 40：闭合区域窗口裁剪（Unreleased）

| 场景 | 输入与参数 | 坐标模式 |

| 窗口裁剪 | 开放路线／闭合区域、矩形窗口；闭合支持填充规则 | 整数／小数，0.3.0 对应演示 |

案例文件只含输入与参数，取材于已有矩形、孔洞、凹轮廓、折线和整数图案构型，不链接参考预期作为结果。点数组编辑器：Boolean/Offset为Paths（多层数组），Stroke/Minkowski路线为Path，图案也为Path；批量加宽及窗口裁剪为Paths。闭合轮廓一般不重复首点；路线末尾返回首点不替代扫掠的显式闭合开关。

图形按数学坐标系显示，x向右、y向上。蓝色为输入区域/操作数A，橙色为操作数B或路线，紫色为局部图案及原点十字，绿色为真实结果。扫掠图案绘于局部原点，路线各顶点对应平移位置；偏置图案不会自动居中。可显隐输入/结果、自适应、按钮/滚轮缩放、拖动平移。绘制通过SVG坐标变换处理y轴，不改变核心语义。区域结果按NonZero复合路径绘制孔洞；开放窗口输入和结果不追加闭合命令、无填充，窗口使用独立虚线。

```json
    "roots": [0],
    "nodes": [
      {"parent": null, "children": [1], "depth": 1, "is_hole": false},
      {"parent": 0, "children": [], "depth": 2, "is_hole": true}
    ]
  }
}
```

paths 保留完整 `[x,y]` 点数组。`nodes[i]` 与 `paths[i]` 一一对应，所有索引在当前响应内有效；根 parent 为 null。空区域 paths、roots、nodes 都为空数组。桥接仅通过公开树访问器，使用迭代队列在同一次遍历中分配轮廓和节点索引，不根据几何猜父子，也不依赖另一次 `to_paths()` 的顺序。传输保留完整点序、绕向和小数值，不保证跨请求节点编号稳定。

面板列出根数、轮廓数、最大深度，以及每个节点的编号、深度、外轮廓／孔洞和顶点数。点击展开箭头收起或展开孩子；点击节点仅高亮对应边界，孔洞不会单独填实。可清除选择，窄屏列表可滚动。主结果始终按 NonZero 复合路径绘制。

三个“层级查看”示例只保存输入：Boolean 展示外轮廓／孔洞／岛；Offset 的矩形孔洞可把 delta 从 2 调到 10 观察消失；Stroke 展示返回起点的开放路线，在 Miter 连接、Square 端点及完整宽度 4 下形成孔洞。首尾重合不改成闭合偏移。

## 显式简化与失败

简化默认关闭。开启时Boolean与Offset调用Closed，Stroke调用Open。Boolean的报告路径索引先排列全部subject，再排列全部clip。显示removed_vertices、removed_per_path及input_degenerate_indices、degenerate_indices、collapsed_indices。

三类退化列表任一非空时，先显示报告并停止后续计算；不补点、不删除路径、不自动过滤。简化不是拓扑修复。Minkowski不隐式简化，切到扫掠时关闭简化开关。

worker调用同一MoonBit编译产物，界面不实现Boolean、Offset、Stroke、Simplify或Minkowski。JSON解析/类型错误与库错误分开返回，库错误保留kind、stage、path_index、vertex_index及适用的轴/值/资源/关联位置。输入编辑立即失效结果，旧请求的迟到响应按请求编号丢弃；失败后无结果层且两个导出按钮禁用。修正后必须重新计算。

## 导出与复现

SVG只导出当前有效结果，包含独立viewBox、白色背景、数学坐标变换与NonZero填充，孔洞保持为空；不需要外部字体、样式或脚本。坐标来自真实结果数组。

平铺 JSON 格式为 MoonClipDemo 版本 1，包含kernel、完整原始request（场景、两操作数/路线/图案、模式、参数、precision、简化选项）、result.paths及simplification统计。可把导出的request再次传给compute复现；结果不从SVG字符串或像素反推。整数结果precision为null；request中的precision在整数模式下不参与量化。

树 JSON 为 MoonClipDemo 版本 2，result 同时包含 output、mode、precision、paths 与 tree，可选 query 用于六类整数／小数区域树的单点或批量定位；顶层 request 仍是可直接重放的版本 1 桥接请求，simplification 保留统计。所有数组、节点、输入参数与简化报告都独立复制。SVG 仍只输出结果轮廓，不输出输入层、节点列表或高亮。

启用简化时先显式简化，再调用所选树入口；简化与几何是两次公开调用，各自建立核心预算。单个树入口内沿用核心累计预算，桥接 JSON 序列化、公开访问器副本和 UI 绘制不计入核心预算。编辑输入、输出模式、精度或参数立即清空摘要、树与选择，禁用导出；错误不会自动改为平铺重算，迟到响应不能重新启用导出。

图案扫掠不额外补满完整端点图案，短路线可留空隙，闭合路线可留孔洞。演示不提供开放Boolean、MinkowskiDiff、带孔图案集合或每路线独立样式。页面显示的耗时仅为worker内单次桥接调用时长，不是基准性能结论。

不依赖浏览器的同类公开调用保留在cmd/example/main.mbt：moon run --target native cmd/example。
