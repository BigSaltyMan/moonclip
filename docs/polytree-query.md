# PolyTree 点定位（0.3.0）

下述增量能力自 **0.3.0** 提供，见[发布记录](release-0.3.0.md)。0.3.1 只修正文档表述，不改变运行库行为或接口；带 Commit 编号的验收记录按原阶段解释。

`PolyTree64::locate(point, limits=) -> Result[TreePointLocation64, ClipError]` 查询已有整数树。点每轴必须在 ±1_000_000_000 内，包含端点。空树返回 Outside，仍检查查询点和限制参数。

| 结果 | 含义 |
| --- | --- |
| `Outside` | 不在任何轮廓内部或边界上 |
| `Inside(node)` | 最深严格包含节点，奇数深度，属于填充区域 |
| `InHole(node)` | 最深严格包含节点，偶数深度，属于孔洞 |
| `OnBoundary(nodes)` | 所有命中轮廓的节点，每个节点一次，顺序不保证 |

外轮廓 [0,0]—[20,20]、孔洞 [4,4]—[16,16]、岛 [8,8]—[12,12] 中，(2,2)、(6,6)、(10,10) 分别返回深度 1 的 Inside、深度 2 的 InHole、深度 3 的 Inside；(4,6) 单独返回孔洞边界。边界优先于内部；两个轮廓仅顶点接触时可同时命中。无边界命中而发现同深度多个严格包含节点时返回 ExecutionFailure，不任选一个。

实现直接迭代私有节点数组，复用精确叉积、点在线段和半开射线规则，使用既有深度；不复制整棵树、不重建包含关系、不递归、不用浮点、epsilon、索引或缓存。最坏线性访问全部轮廓顶点；没有索引查询性能承诺。

每次公开调用独立建账。`max_input_paths` 限制树轮廓数，`max_input_vertices` 限制所有轮廓的顶点总数；查询点不计作路径或轮廓顶点。防溢出的规模预检后直接使用受控树数据，不重复验证坐标与拓扑。合法的大树也可能被本次较小限制拒绝。默认内部预算不变，私有注入账本的限制和历史用量保持权威。

计费覆盖规模与节点访问、边访问、边界数组、数组槽、节点视图、深度矛盾检查所用的 Map 及结果，分配前收费且不退款。单点入口的所有错误使用 PolyTreeQuery，路径和顶点索引均为 None，不把内部节点索引当作原始输入。预算失败不返回部分列表，不修改树或跨调用保存状态。

返回节点沿用不可变视图；OnBoundary 每次返回独立数组。修改该数组或 `contour()` 返回的副本不影响树及后续查询。整数树支持单点及批量定位；小数树见下文。不包括最近边距离、空间索引或拓扑修复。历史参考数据不构成本入口的执行证据。

## 批量查询（自 0.3.0，Commit 48）

`PolyTree64::locate_many(points, limits=) -> Result[Array[TreePointLocation64], ClipError]` 保持输入顺序和重复项，结果长度与输入相同。每个点仍遵守上述四种状态、边界优先、全部边界命中及最深包含节点规则。重复边界点分别创建数组，修改一项的边界数组不影响另一项、树或后续查询；节点仍为不可变树视图，轮廓访问器返回副本。

执行顺序为限制检查、树规模预检一次、全部点校验、创建批量结果数组、逐点定位并保存。任一点非法或预算不足，整批返回 Err，不返回部分成功项。空列表仍检查限制和树规模，成功返回已计费空数组；空树上的点仍须合法，合法点均为 Outside。输入点数组和树均不修改，不保留跨调用状态。

查询列表不计作额外路径或轮廓顶点。`max_input_paths` 和 `max_input_vertices` 仍只限制树规模，顶点数通过剩余额度递减防溢出。没有新增查询数量计数器；工作量及结果存储受原内部预算约束。传入私有账本时，以其限制及历史用量为准，不重置或退款。

| 批量新增费用 | 节点 | 工作 |
|---|---:|---:|
| 每个点的两个坐标轴校验 | 0 | 2 |
| 批量结果容器（全部点验证后创建） | 1 | 0 |
| 每个结果槽及追加 | 1 | 1 |

树规模预检和每次求值沿用原收费：每个轮廓规模访问 1 工作；每个查询新建边界数组及深度 Map 共 2 节点；节点、边各访问 1 工作；包含分支和边界追加各 1 工作；深度记录 2 节点，边界视图及槽 2 节点；Outside／OnBoundary 结果 1 节点，Inside／InHole 结果及视图 2 节点。分配前收费，费用逐项累计，不直接乘加查询长度。旧 `locate` 仍按“限制 → 点校验 → 树规模 → 定位”执行，未加收批量校验、容器或槽费用。

批量错误均为 `PolyTreeQuery`，path_index 为 None；点校验及逐点评估错误的 vertex_index 是 points 中的零基索引。树规模或批量容器错误的 vertex_index 为 None，内部节点编号不充当查询点位置。旧单点索引保持 None。

此实现直接复用精确定位辅助，不循环调用公开 `locate`，不重复预检树规模。设树有 V 个轮廓顶点，查询数为 Q，逐点求值最坏仍为 O(Q×V)，另有一次树规模及 O(Q) 点校验开销。不引入空间索引、持久缓存或浮点计算，不预设性能提升幅度。网页的整数查询已在 Commit 49 接入单点／批量；旧参考清单不构成新增方法的执行证据。

Commit 48 当时仅新增 `tree locate batch:` 三项：有序状态与独立边界结果、后续非法点及空输入、确定额度下的累计耗尽。三层矩形的外部点单次定位费用仍为 18 工作／3 节点；批量白盒据计费规则设定额度，不搜索阈值。完整入口静态预期由 2400 调整为 2403，仅表示新增三项，不宣称执行过全量。

本地 Windows 已执行 `bash scripts/check.sh --scope tree-locate-batch`：native、JS 各 3/3，格式、接口差异、两目标静态检查及 CLI 示例通过。普通 Linux CI 使用同一轻量入口，按最终提交 SHA 核对；未运行库全量、全部工具测试、参考重建、演示／浏览器、性能或候选验收，没有修改版本或发布。

## 小数树查询（自 0.3.0，Commit 50）

`PolyTreeD::locate(point, limits=)` 返回 `Result[TreePointLocationD, ClipError]`；`locate_many(points, limits=)` 返回同类型结果的有序数组。结果仍为 Outside、Inside(node)、InHole(node)、OnBoundary(nodes)，节点类型为 PolyNodeD。全部既有小数区域树入口均在共同转换时保存原建树 Precision，包括空树；调用者不需要、也不能为查询另传精度。

查询点先按原 Precision 检查有限性、原单位范围及半整数远离零量化，再判断相对于整数区域的位置。例如边界 x=0、点 (-0.004,1)，在 Precision=2 的树上落到边界，在 Precision=3 的树上仍在外部。这是量化后的位置，不是任意精度实数位置；不使用 epsilon，也不对解码 Double 轮廓做近似叉积。不同查询点量化到同一个网格位置是合法的，不使用几何输入的碰撞表，顺序与重复项保留。

一次调用先检查限制及所有查询点，再预检树规模并恢复一份临时整数视图。视图深复制原有轮廓、根、孩子索引及深度，不调用 tree_build 或 Boolean、不重新判断包含关系。批量只恢复一次并逐点复用已验证的精确整数定位逻辑；结果根据原节点索引映射回原小数树的不可变视图，不引用临时网格。OnBoundary 每项新建数组，修改结果数组或访问器副本不会影响其他项或树。任一步失败整批 Err，不发布部分结果、不修改输入、不保留缓存。

### 网格恢复的误差范围

设整数网格坐标为 k，|k|≤10^9，倍率 s=10^d、0≤d≤6。k 和 s 均可被 binary64 精确表示；非零 k/s 的绝对值至少 10^-6，处于正规数范围。令单位舍入误差 u=2^-53，存储值 v=fl(k/s)，乘回值 r=fl(v×s)，则 `|r-k| ≤ |k|(2u+u²) < 2.23×10^-7 < 0.5`。k=0 时两步均精确为零。因此用既有 decimal_round 可恢复原 k，不需 epsilon 或坐标钳制。

恢复前检查有限性及安全转换范围，恢复后再次用原 decimal_value 解码，与存储 Double **严格相等**才接受；不一致返回 PolyTreeQuery / ExecutionFailure，位置为 None，不放宽比较。精度只作为现有 TreeDataD 对象的私有字段保存，不新建元数据容器，也不长期保存整数轮廓。原转换的逻辑收费仍为 `4+5N+2V` 节点、`1+2N+V` 工作；保存精度没有增加逻辑对象。

### 小数查询预算与错误

每次公开调用独立建账，批量所有点共用账本。Limits 仍限制树的轮廓数及全部轮廓顶点数，不把查询点当作输入路线。规模通过剩余额度递减检查防溢出，传入私有账本时以其限制和历史消费为准，不重置、不退款、不提高默认预算。

| 环节 | 逻辑节点／工作 |
|---|---|
| 每点量化 | 1 节点、2 工作；批量另收每点 1 槽及整个量化数组 1 容器 |
| 树规模预检 | 每轮廓 1 工作，一次 |
| 临时整数视图 | `4+5N+2V` 节点、`1+2N+V` 工作；每顶点单位含两轴恢复及严格回解码 |
| 整数定位 | 沿用已有每点临时容器、节点／边访问、深度记录、结果及边界视图费用 |
| 小数映射 | Outside 1 节点／1 工作；Inside、InHole 2 节点／1 工作；OnBoundary 2 节点／1 工作，另每命中视图及槽 2 节点／1 工作 |
| 批量结果 | 1 容器，每项另 1 槽／1 追加工作 |

所有分配前收费，逐项累加而非直接乘加输入长度。空树仍校验点；空查询列表仍预检规模、恢复已计费视图并返回已计费空数组。查询具有一次临时视图构造成本，批量可分摊这一成本，但仍逐点线性访问全部轮廓顶点，无空间索引或性能幅度承诺。

所有查询错误阶段为 PolyTreeQuery。单点位置为 None；批量点量化、求值或映射错误的 path_index=None，vertex_index 为查询点零基位置。树规模、临时恢复及整体容器错误没有对应查询点，位置为 None。非有限点沿用 QuantizationFailure，原单位越界沿用 DecimalCoordinateOutOfRange，均保留轴信息；空树也按自己的原 Precision 限定范围。

Commit 50 当时只新增 `decimal tree locate:` 三项，覆盖完整三层节点、原精度差异、量化后同点、非法后续点、少量边界精度标量恢复，以及原转换费用和源树复制隔离。白盒用确定额度验证共享账本在第二点求值失败后独立重试成功，不搜索预算阈值。完整入口预期计数改为 2406，仅作配置维护，不表示本笔执行过全量。Commit 50 当时的网页只支持整数单点／批量查询；当前小数界面见下方 Commit 51 章节。

Commit 50 的历史验收：2026-10-24，Windows 本地 `tree-locate-decimal` 轻量入口通过：native、JS 各 3/3，格式、公开接口差异、两目标静态检查及 CLI 示例通过。普通 Linux CI 按最终源码 SHA 单独核对。未运行全量、全部工具测试、参考重建、演示／浏览器、性能或候选验收，未发布。


## 网页小数查询（自 0.3.0，Commit 51）

网页现已接入全部六类小数区域树的单点／批量查询，直接对当前操作生成的同一树执行核心 locate 或一次 locate_many，再编码同一树。查询没有第二份 Precision，沿用本次建树精度。列表及图中点位始终保留原始输入坐标；结果是量化后的判定，原始标记可能看起来稍离边界，不代表核心在该实数位置进行近似判断。

沿用最多 32 点的演示限制、单点／批量互斥及 v2 请求重放，空列表可导出。整数模式仍拒绝小数，小数接受有限值；范围和量化由核心负责，后续非法点保留 vertex_index，失败没有部分结果。SVG 只包含区域，不包含查询或高亮。单点步长随模式切换，查询行选择不重新计算几何。上文 Commit 48／50 的“当时仅接整数”说明保留为历史范围，当前网页能力以本节和[演示说明](demo.md)为准。
