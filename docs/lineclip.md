# 开放折线与闭合区域求交（Unreleased）

`intersect_polylines(paths, clip, fill_rule=EvenOdd, limits=)` 返回 `Result[Paths64, ClipError]`。该接口仅在开发源码中提供，版本元数据仍为 0.3.2；已发布 0.3.2 不包含它。受检示例见 [run_lineclip_example](../cmd/example/main.mbt)。

小数入口 `intersect_polylines_d(paths : PathsD, clip : PathsD, precision=, fill_rule=, limits=)` 返回 `Result[PathsD, ClipError]`，同为 Unreleased，Precision 默认 3、支持 0—6。两侧先共同量化到一个网格，只有 clip 做闭合有效性检查，再复用下述整数求交并按原精度解码。原始小数与网格几何的区别见[小数适配](decimal.md)。

整数 `difference_polylines(paths, clip, fill_rule=EvenOdd, limits=)` 返回 `Result[Paths64, ClipError]`，表示开放路线减去闭合填充区域。它同样仅在开发源码中提供，未包含在已发布 0.3.2 中；目前没有小数求差入口。

| 操作 | 保留区间 |
| --- | --- |
| `intersect_polylines`／`intersect_polylines_d` | 最终填充区域内部及边界 |
| `difference_polylines` | 最终填充区域外部，包括孔洞 |

`paths` 是独立的开放路线，不隐式连接首尾；显式返回起点则按真实输入线段处理。`clip` 是共同按 EvenOdd 或 NonZero 解释的闭合填充区域，可以有孔洞、重叠、自交或退化轮廓。先调用一次已有私有 Boolean Union 确定该区域，再沿路线切分，不逐轮廓裁剪后拼接，也不将开放边加入扫描器。

## 片段与边界

保留**最终填充区域内部及边界上的非零长度区间**。边界重合段保留；单点相切没有片段；孔洞会切开路线。EvenOdd 抵消的轮廓不再是最终边界，不能因为原始边线重合而产生输出。零长度段不产生片段，原始顶点仍计入额度。

以上为求交规则。求差保留相反的区间，剔除内部及正长度边界重合段；孔洞属于区域外部。区间归属与输出端点不同：进入／离开区域的切分端点仍可在边界上，不能称输出每个点都严格位于外部。仅在孤立点相切不会拆开连续外部路线；有被剔除的正长度区间则必须分片，即使舍入后端点相同也不重新连接。EvenOdd 抵消后的原始边线不构成擦除区域。

不同路线不拼接，结果按原路线顺序及行进方向排列。保留有效片段中的普通共线输入顶点，不排序、反向、补闭合边或自动简化。自交路线按自己的行进次序处理。输出内外数组独立，不引用调用方可变数组；任一步失败返回完整 Err，不修改输入、不暴露部分片段，独立重试不受上次临时状态影响。

[Clipper2 开放路径说明](https://www.angusj.com/clipper2/Docs/Overview.htm)对部分共线重合段按相邻段位于内外及较低相邻段的位置决定包含。这里的求交统一包含最终区域边界，求差统一移除正长度边界重合区间；两者与这些规则有意不同，**不宣称逐项兼容 Clipper2 开放裁剪**。没有新增上游参考清单或兼容性统计。

## 数值路线

所有输入每轴仍限制在 ±10^9，包含边界；直接比较范围，拒绝任意 Int64 极值而不先取绝对值。闭合区域阶段沿用已有 Boolean 的整数交点离散化、清理及方向规则。后续裁剪针对**该整数区域**，不声称恢复理想实数原区域。

每个非零路线段收集 t=0、t=1、普通交点及共线重合端点。Int64 精确叉积的分量差至多 2×10^9，行列式绝对值至多 8×10^18，仍在 Int64 内。事件用正分母有理数表示，BigInt 交叉相乘排序、去除相同参数。用相邻参数的精确有理中点及半开射线分类，边界先判断；不转 Double，不用 epsilon，没有水平／垂直边的近似特例。

事件分母小于 2^63；中点分母小于 2^127，插值与分类中间值保守不超过 192 位。因此本入口的 BigInt 操作数位宽有固定坐标域上界，不随事件总数累积增长；每个区间重新由两端事件构造。

输出坐标以正分母上的整数商和余数实现**半整数远离零**舍入，正负数使用同一规则。分类与片段是否连续先由精确事件确定，舍入只用于存储结果。舍入导致的连续同点可消除；不足两个不同点的片段丢弃。被剔除区间两侧即使舍入后端点相同，也分别结束，不能跨过它重新拼接。

这与旧 `rect_clip_lines` 及其小数包装的向零截断和特殊贴边规则不同。旧入口实现不变，不改为调用本入口。这里提供整数／小数求交及整数求差，没有 Union、Xor 或树输出。源码网页的独立“区域裁线”页签仍只提供整数／小数求交，未接入求差；矩形窗口页签仍使用原入口。

## 预检、位置与累计预算

开放路线与 clip 原始路径数、整理前顶点数共同占用输入额度，空路径及重复点照计。组合索引为 paths 在前、clip 在后；clip 路径索引加上原始 paths.length()。在复制、区域规范化、事件或结果容器构造之前完成原始数量和坐标检查；空区域也不能绕过非法路线。

入口校验使用 LineClipParameters。原始数量累加复用剩余额度递减的防溢出预检，费用为 2P+V 工作（P 为合计路径数，V 为原始顶点数）。区域阶段通过 internal_input 传入已经验证的 clip，不再占用原始输入额度；其内部错误没有调用方位置，保持 None 及真实引擎阶段。路线段事件／分类使用 LineClipEvaluate，能对应时保留原路线和段末顶点索引。输出和舍入使用 LineClipOutput，位置 None。

全部阶段共用一个 CallBudget；注入账本的限制及历史消费保持权威，不重置、不退款、不提高默认上限。区域求值、清理和提取沿用已有引擎计费。新增逻辑分配及工作在执行前收费：

| 新增工作／存储 | 逻辑节点 | 工作 |
| --- | ---: | ---: |
| 内部空操作数、事件数组、最终结果或每个片段容器 | 各 1 | 0 |
| BigInt 转换、加减乘、除、余数、取负的每个结果 | 各 1 | 各 1 |
| BigInt 比较 | 0 | 各 1 |
| 有理参数／插值点对象（引用已计费 BigInt） | 各 1 | 0 |
| 事件或输出数组新槽及追加 | 各 1 | 各 1 |
| 有序插入每个槽移动 | 0 | 各 1 |
| 路线、线段、轮廓、边或区间访问 | 0 | 每次 1 |
| 候选参数范围检查、输出连续去重、片段结束检查 | 0 | 每次 1 |
| 输出 Point64 | 1 | 0 |
| 输出 Int64 转换及两次安全范围比较 | 0 | 3 |

Int64 边访问工作包含有界叉积和普通分支；BigInt 临时值单独经计费辅助构造。常量倍率的 BigInt 也收费，复用不可变操作数不视为复制。逻辑节点数不等同于实际字节或后端 BigInt limb 分配数量。重复事件、丢弃点及失败所消耗的费用不退还；空结果容器也收费。

求差只通过私有 KeepOutside 选择策略取反分类；默认 KeepInside 供原整数／小数求交使用，不新增旧分支的分配或收费。事件、中点、边界判断、舍入、片段结束及连续去重保持原样。空擦除区域也先检查全部输入，再独立构造有效开放片段；这不是保留所有重复点的原样复制，空路径、单点及零长度段不产生片段。

没有空间索引或扫描线级性能承诺。设路线非零段数为 S、规范区域边数为 B，每段至多 2B+2 个候选事件。有序插入排序最坏 O(B²)，逐区间扫描全部边也为 O(B²)，路线阶段总计最坏 O(S(B+1)²)，另加区域 Boolean 的成本。复杂输入可因累计事件、比较和分类触及默认预算，即使原始数量合法也可能失败。

## 小数适配及其定向验证

独立小数流程为 `decimal_precheck(paths, clip)` → 一次开放规则共同量化 → 仅 clip 的 `decimal_closed` → 私有 `line_clip_execute` → `decimal_output`，错误经 `decimal_error` 映射。两侧共享输入额度和碰撞表，clip 检查索引为原始 paths.length()+clip 索引；允许空闭合轮廓，非空闭合网格退化时报错，不以有向面积筛掉自交输入。开放路线不做闭合有效性检查。空区域仍校验原始数量、坐标及量化，几何输入不同位置合并会报错。

小数入口不跳过整数原有预检和收费，两次预检、量化、区域求值、事件及解码均在同一账本；仅新增 clip 外层访问每条 1 工作，其他逻辑复用原收费。限制和历史消费保持权威，失败不退款、无部分结果、输入隔离。正零解码沿用既有规则；输出依次经过输入网格量化、整数区域规范化、精确有理切分、网格交点半整数远离零舍入及 Double 解码，不承诺理想实数结果。

小数适配仅三个 `decimal line clip:` 测试块，分别覆盖完整带孔片段及双向隔离、混合量化及真实组合位置、默认精度手工斜线结果及整数成功后解码耗尽。`bash scripts/check.sh --scope lineclip-decimal` 仅运行这三项、两目标静态检查及 CLI 示例，不追加整数筛选。完整入口期望维护为 2412，仅为配置数；没有运行全量、工具全集、参考重建、性能、浏览器或候选包检查。现有参考案例和能力检查数不变。

## 区域裁线交互演示（Unreleased）

在源码演示的“路线实验 → 区域裁线”编辑开放路线集合与闭合裁剪区域，选择整数／小数、Precision 和 EvenOdd／NonZero，点击计算。场景固定 Intersection，不提供树、查询、简化、连接或端点参数。两个案例分别为整数带孔矩形和相同构型的小数版本，案例只保存输入，不保存输出。

`scene: lineclip` 在通用闭合输入准备之前分派，分别一次调用 `intersect_polylines` 或 `intersect_polylines_d`；前端不量化或求交。闭合区域合并为一个 SVG path 按所选规则填充，路线与实际 `geometry: open-paths` 响应不闭合、无填充。摘要保留片段数、顶点数、原路线数、模式、精度、填充及“保留最终区域边界重合段”提示。

输入或参数变化立即清除有效结果并禁用导出，失败没有部分结果；迟到响应仍受编号保护。核心的组合路径位置保持路线在前、区域在后，桥接整数／结构解析也采用该偏移。导出复用通用开放 SVG（只含实际片段）和 v3 JSON（含完整 paths、clip、参数和结果）；重放将 request 按原 scene 重新送入核心，不读取保存结果。旧窗口裁剪 v3 和区域 v1／v2 分派不变。

本笔扩展既有三个 `demo rectclip:` 桥接／导出检查，不新增测试块、库测试或 scope；普通 CI 使用 `demo-rectclip`。浏览器实际下载、重放及窄屏观察见[演示验收](demo-acceptance.md)。能力仍为 Unreleased，已发布 0.3.2 不包含它们。
