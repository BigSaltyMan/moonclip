# MoonClip 0.2.0 发布候选说明

状态：**待发布**。当前只确定版本并验收源码候选，尚未正式上传 Mooncakes、创建 v0.2.0 标签或 GitHub Release，也未从注册表验证 0.2.0 安装。正式上传另行取得针对冻结候选的明确授权。本页没有填写发布日期。

已发布的 0.1.0 及其[历史发布记录](release-0.1.0.md)、注册表安装证据、归档校验和和标签保持原样。候选生成与解压消费者成功不等于新版本注册表安装成功。

## 相对 0.1.0 的增量

- 五个公开函数：`boolean_tree_d`、`offset_tree`、`offset_tree_d`、`stroke_tree`、`stroke_tree_d`。整数 `boolean_tree` 已在 0.1.0 中提供。
- `PolyTreeD`、`PolyNodeD`，以及树的 `roots()` / `to_paths()` 和节点的 `contour()` / `children()` / `depth()` / `is_hole()` 访问方式。
- 树构建及小数解码的累计预算、失败清理和访问器复制隔离；偏移／描边树表达最终区域，描边保留完整宽度和单条开放路线的端点语义。
- 六个树入口的交互层级、轮廓边界高亮及保留结构的 v2 JSON；原平铺行为及 v1 JSON 保持兼容，SVG 仍只导出结果区域。
- [升级说明](upgrade-trees.md)、[增量验收](acceptance-trees.md)和真实候选包的 native／JS 六入口消费者。

详细契约见[支持范围](scope.md)、[小数树](decimal.md#unreleased小数孔洞树)及[组合说明](composition.md)，实际接口见[根公开接口](../pkg.generated.mbti)。小数层级取决于量化网格；平铺成功不保证树输出也有足够预算；`to_paths()` 不保留显式父子关系。

## 候选生成与冻结

执行 `python scripts/check_release.py --report _build/release-0.2.0/report.json`。固定工具链正式生成实际 `moonclip-0.2.0.zip`，逐成员审计文件集合、原始字节、大小、SHA-256、许可、来源与相对链接，再在仓库外解压，通过 moon.work 对 native、JS 分别运行六个树入口和原有断言。这是候选消费者验证，不是注册表安装验证。

文件数与 ZIP 大小按实际结果记录，不固定沿用 Commit 24 的 50 文件／213274 字节。Windows、Linux 分别保存归档校验和，逐成员路径及内容哈希对应冻结提交。完整候选 SHA、同 SHA CI、清单、校验和及结果在提交后的交付记录中承载，避免为填写自身 SHA 反复补提交。

库测试仍为两目标各 2323，工具 281，桥接／导出 20。既有 CI 在最终候选 SHA 完整检查一次；push 仅匹配分支，保留 PR 检查，后续创建标签不重复触发同一全量任务。

## 授权后的正式发布流程

上传前重新核对实时版本规则、BigSaltyMan 账号与模块权限、0.2.0 占用、GitHub 写权限及 v0.2.0 标签／Release 不存在，并确认仓库外发布目录逐文件对应冻结候选。版本已占用、权限不足或候选需要修改时停止，不自动改版本或覆盖。

获得授权后，从仓库外一致源码目录使用固定工具链支持的发布命令。非零退出、超时或不明确响应先查询注册表，避免盲目重传；dry-run 不作为正式发布。上传成功后核对版本、撤回状态和服务端校验和。

另建不使用 moon.work、本地路径或候选库副本的仓库外项目，从注册表获取精确 0.2.0，核对依赖来源与实际下载文件，并分别执行 native／JS 六入口消费者。通过后才能补写“Mooncakes 安装验证通过”，再创建精确指向冻结源码的 v0.2.0 和 GitHub Release，上传实际发布 ZIP、SHA256SUMS.txt 与无敏感信息的摘要。v0.1.0 不移动或覆盖。

本页随后只按已发生事实补充发布版本、源码 SHA、Mooncakes／Release 链接、时间、清单和校验和、注册表消费者及同 SHA CI。发布后状态文档提交与发布源码 SHA 分开记录，不为更新包内待发布文案重新上传同一版本。
